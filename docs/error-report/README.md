## 0. 先記住的五條規則

所有情境的結果都由這五條決定,後面只是套用:

1. **錯誤有四種長相。** 整塊卡片(`DataBoundary`:標題「這個區塊載入失敗」+「伺服器回應 N,請稍後重試」+ 後端 message 小字 + 重試鈕)、行內(對話泡泡裡的紅字、Artifact 內容區的一行提示、修復卡)、右上 toast(操作失敗)、全頁蓋版(只有 403)。
2. **文案由 `code` 決定,不是後端的 `message`(ADR-0016)。** 字典只認 5 個 code:`CONFLICT`、`FILES_EXPIRED`、`PARSE_ERROR`、`UPLOAD_LIMIT`、`UNSUPPORTED_TYPE`。其他 code 一律退到「伺服器回應 N」,後端句子降為小字。**例外**:對話泡泡裡的執行錯誤、修復卡的失敗行、403 蓋版,這三處直接印後端原句。
3. **重試:query 自動重試 1 次(約 1 秒後),mutation 不重試,所有請求都沒有 timeout(ADR-0007)。** 後端掛住不回時,畫面停在 spinner 上永遠不會變成錯誤。
4. **403 是唯一有全域處理的狀態碼。** 任何一支 API(含背景 refetch、MCP call)回 403,整個 app 蓋上不能關的蓋版,顯示後端自己的 message;其他地方為了不說兩次都閉嘴。**401、429、瀏覽器離線都沒有任何處理。**
5. **`useSuspenseQuery` 一失敗就往上丟到最近的 boundary。** 所以「哪個 query 在哪個 boundary 底下」決定了倒掉的範圍。側邊欄的 boundary 底下有 `GET /sessions` **和** `GET /artifacts`;Artifact 面板的 boundary 底下有 `GET /sessions/:id` 和 `GET /artifacts`;對話欄底下有 `GET /sessions/:id`;composer 自己一個 boundary 底下有 `/config` 和 `/connectors`。

### 1.5 修復提議(圖 11–14)

**入口三種**:iframe 丟 `erd-artifact-error`;MCP call 回 `TOOL_ERROR`/`INVALID_CALL`(只在 Studio,全頁模式關閉);iframe 送格式錯的 `erd-mcp-call`。

**store 規則**:agent 正在回答 → **直接丟掉,不排隊**(ADR-0015 §run-in-progress-wins,昨天改的);同一個 artifact 已有提議或已在佇列 → 丟掉(第一批贏,後面可能更有用的錯誤都沒了);按過「忽略」的 artifact → 這個分頁裡永遠不再提;切換對話 → 提議與佇列清空,忽略清單留著。

| `POST /artifacts/:id/repair` 回應 | 卡片                                                                    |
| --------------------------------- | ----------------------------------------------------------------------- |
| `{repaired: true}`                | 卡片消失、內容 invalidate、iframe 重掛                                  |
| `{repaired: false}`               | 「修復未成功」+ 再試一次(圖 12)                                         |
| 409 `FILES_EXPIRED`               | 「檔案已過期,無法修復此 Artifact」+ 知道了,不給重試(圖 13)              |
| 5xx / 網路                        | 「修復未成功 — 後端原句」+ 再試一次                                     |
| 403                               | 也是「修復未成功」,**沒檢查 `isAccessDenied`**,蓋版底下多一行沒人看的字 |

**缺口**:修復成功後的 `bumpArtifactReload()` 是全域的,無條件執行——使用者若已切到別的 artifact,那個也會被重掛(程式註解說只重掛自己的,跟程式不符);修復請求沒有 abort。

### 2.2 清單失敗(`GET /artifacts`)(圖 22)

這是影響最大的一支:三處都用 suspense 讀它。

- **側邊欄**:`ExpandedSessionRail` 為了 Artifacts 旁的數字先讀它 → 整個側邊欄(開新對話、Artifacts、Skills、所有 session)換成卡片。
- **landing 自動選取不會跑** → 沒有 session 被選 → 對話欄顯示「開始分析」空狀態、Artifact 面板顯示「尚無 Artifact」——**兩個面板在對使用者說「你什麼都沒有」,其實是清單壞了**。
- **Artifact 面板本身**也在 frame 之上讀它:即使 `GET /artifacts/:id` 能成功,面板整個換成卡片。
- 收合側邊欄不讀清單,所以收合起來反而躲得過(意外的 workaround)。
- `GET /sessions` 失敗的結果跟這個一模一樣。

### 2.3 訊息裡的 artifactId 不在清單

版本列來自訊息不是清單,所以列還在;標題退回訊息的字、`publishedAt` 不明 → 顯示「發布」鈕而不是「已發布」、分享停用(「發布後才能分享」)。被刪的 artifact 仍在選單裡,選了就是 2.1 的 404。

### 2.5 iframe 本身

- `sandbox="allow-scripts"` 只此一項;`srcDoc`;CSP `default-src 'none'; script-src <origin> 'unsafe-inline'; style-src 'unsafe-inline'; img-src <origin> data:; connect-src 'none'` 塞在 `<head>` 最前;scrollbar 樣式塞最後;昨天加了白底。
- **沒有 onLoad/onError、沒有載入 timeout**:文件掛住、無窮迴圈、完全不畫,都是一張白矩形,只有重整可按。
- 兩次 `DOMParser` 解析+序列化都在主執行緒,**沒有大小上限**;`<!DOCTYPE>` 會被正規化、`<html>` 外的節點被丟掉。
- `erd-artifact-error`:只驗 `event.source === iframe.contentWindow`(對 sandbox 的 opaque origin 這是正確且唯一可行的檢查;別的視窗、分頁、extension 的訊息都會被丟掉)。**payload 完全不驗**:`errors` 不是陣列、沒有 message、幾 MB 的字串,都會進 store、進修復卡、進 `POST /repair`。
- 錯誤風暴:同一 artifact 只留第一批。
- **全頁模式**:MCP 修復關了,但 `erd-artifact-error` 的收集是無條件的 → 錯誤寫進 store,那頁沒有東西畫它,回 Studio 時可能對一個已經離開的 artifact 冒出提議(ADR-0017 有記)。

### 2.6 MCP bridge(`erd-mcp-call` → `POST /artifacts/:id/mcp-call` → `erd-mcp-result`)

| 情況                                          | 結果                                                                                         |
| --------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 訊息沒有 `id` 或不是 `erd-mcp-call`           | 靜默丟掉(沒人可回)                                                                           |
| 有 `id` 但 connector/tool/args 格式錯         | 不打網路,直接回 `INVALID_CALL`,並提修復                                                      |
| 後端回 `TOOL_ERROR` / `INVALID_CALL`          | 原樣轉給 iframe + 提修復(訊息 `MCP call TOOL_ERROR: tool "x" on connector "y": …`,`line: 0`) |
| `AUTH`、`RETRYABLE`、`CONNECTOR_*`、未知 code | 原樣轉給 iframe,**前端什麼都不畫、不重試**(Cowork 是信差,ADR-0017)                           |
| HTTP 400 / 404 / 401、403 / 其他、離線、5xx   | → `INVALID_CALL` / `CONNECTOR_NOT_ALLOWED` / `AUTH` / `RETRYABLE`;403 同時觸發全頁蓋版       |
| **body 帶已知 code 就蓋過狀態碼**             | 500 但 body 寫 `code: "TOOL_ERROR"` → 被當成工具錯誤並提修復                                 |
| 30 秒沒回                                     | abort → `RETRYABLE`「no answer within 30s」                                                  |
| 同時超過 8 個 call                            | 第 9 個起排隊,**佇列無上限**,每一個最後都會真的打出去                                        |
| 同一個 `id` 用兩次                            | 不去重,兩個各自回,iframe 自己處理                                                            |
| iframe 重掛/卸載時還有 call 在途              | 全部 abort、不回、不提修復                                                                   |

### 2.7 執行中

- 串流收到 `ARTIFACT` 事件那一刻就推到右側,版本列多一列合成的「v N+1」直到歷史 refetch 追上。
- **run 在 artifact 到之前失敗**:右側不動,維持上一版或空狀態;**右側沒有任何「這次失敗了」的狀態**,只有對話欄在說。
- artifact 到了但內容 404/500:版本列有它、工具列有、內容區一行提示;下個問題不帶 `baseArtifactId`。

### 2.8 全頁模式(`/cowork/artifact/:id`)

- 內容 404 → 「找不到 Artifact。」(沒有 `role=status`,面板那邊有,不一致);其他 → 「載入失敗」。
- 清單失敗 → 整頁卡片,只剩 app header。
- **分享鈕的 tooltip 在 artifact 不在清單時說「只有原擁有者可以分享」**——其實只是沒列出來,使用者會照這個錯的理由去找別人。
- `/cowork/artifact/`(沒 id)→ **整個內容區空白**,只有 header。

## 5. 問題清單(依嚴重度)

**P1 — 使用者會被誤導或卡死**

1. **401 沒有任何處理。** SSO 過期後每個面板都是「伺服器回應 401 / 請稍後重試」,重試無效、沒有導向。
2. **`GET /artifacts` 或 `GET /sessions` 失敗會拖倒整個側邊欄,而且另外兩個面板會顯示「你還沒有對話 / 尚無 Artifact」的空狀態**,對使用者說錯的事。Artifacts 的數字應該自己一個 boundary 或改非 suspense。
3. **失敗的 run 不 refetch 歷史、沒有重試鈕。** 斷線時後端寫的「回應已中斷」紀錄看不到,「請重新送出一次」但沒有按鈕;成功的 run 有 refetch,Stop 有輪詢,唯獨失敗沒有。
4. **英文與 JS 訊息外洩**:非 JSON 的串流拒絕印 `Unknown error`;render 炸掉時卡片印 `TypeError: …`。
5. **無 timeout**:掛住的後端 = 永遠的 spinner,無任何出口(ADR-0007 為了大檔上傳而全關,但讀取沒有理由跟著)。

**P2 — 明顯的缺口**

6. session 404 用通用文案,專屬句 `errors.notFound.session` 接不到載入路徑。
7. Artifact 內容空字串 → 空白無字;非 HTML → 原文當 Artifact 顯示;沒有 content-type 與大小檢查;iframe 無 load timeout。
8. tab focus 的背景 refetch 沒有 staleTime,瞬時 5xx 會炸掉已畫好的側邊欄,403 會鎖住正在讀的人。
9. Markdown lazy chunk 沒有自己的 boundary;router 沒有 `errorElement` 與 `*` 路由。
10. `erd-artifact-error` payload 不驗、不設上限;MCP 佇列無上限、id 不去重;body 帶 code 可蓋過 500。
11. 全頁模式的 JS 錯誤寫進 store 但沒人畫;分享 tooltip 對「未列出」說「非擁有者」。
12. 修復成功的重掛是全域的、無條件的;修復不檢查 403、無 abort。
13. 回答中不能重整,即使失敗的是舊 artifact。

**P3 — 小的、或設計上接受的**

14. 卡片不說自己是哪個區塊;重試無上限無退避;兩層一樣的 Thread boundary。
15. `ANSWER` 事件從不渲染;壞掉的 SSE 區塊靜默丟棄。
16. 忽略過的 artifact 這個分頁永遠不再提;錯誤風暴只留第一批。
17. 開新分頁被擋不說;複製失敗靜默;`errors.notFound.connector` 沒人用;`BROWSER_REPAIR_UNSUPPORTED` 沒文案。
18. 沒有錯誤回報、mutation 失敗不 log、DEV-only 的未知 code 警告。

**這份只描述現況,沒有改任何程式。** 要動哪幾條你決定;我的建議是先做 1、2、3、6(都是小改動、影響最大),5 的 timeout 可以只加在 GET 上。
