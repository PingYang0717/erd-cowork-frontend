# 0006. 執行時不再有 mock 後端,未實作的端點回 stub 或在 UI 停用

日期:2026-08-28

## 背景

在後端還沒開始開發時,整個 app 由 MSW 服務:一個環境變數決定哪些請求穿透到真後端,
其餘由 `handlers.ts` 以 localStorage 為後盾應答。

這在「還沒有後端」時是對的,一旦後端進入開發就開始說謊。畫面上按得動的東西有兩種
來源——後端真的有的,以及 mock 編出來的——而使用者、甚至開發者,都分不出是哪一種。

## 決策

1. **runtime 不啟動 MSW。** `main.tsx` 直接 mount;沒有傳輸模式開關、沒有
   `mocks/browser.ts`。只有一種模式:打真後端。
2. **後端未實作的讀取,在 api 模組回 stub**——就寫在它假裝的那個函式旁邊,不抽成
   `stubs/` 目錄,這樣呼叫端一眼看得出哪條是假的。目前兩條:`GET /connectors`
   (且已改制——目錄是前端常數,連線狀態是使用者偏好存 localStorage)與
   `GET /directory`(分享對話框搜尋收件人用)。
3. **後端未實作的寫入,在 UI 停用**,標示「後端尚未支援」。按鈕用既有的延遲 Tooltip;
   選單項目不行(停用的項目吞掉 pointer event),所以理由直接寫在畫面上
   (`UnsupportedLabel`)。
4. **停用的粒度是入口。** 不讓對話框開得起來、填完才發現送不出。
5. **api 的寫入函式即使沒有呼叫端也保留**,標註原因。它們是
   `docs/api/interface.md` 的可執行版本,後端補上那天,UI 只要拿掉一個 `disabled`。
6. **連不上後端就顯示連不上**,不 fallback 到 stub。
7. **測試繼續跑 MSW。** `mocks/` 是 test-only,只服務後端真的有的那幾條加上 SSE 劇本。

## 後果

**得到**:畫面上看到的就是後端真的有的。「這條還沒接」變成 UI 上看得見的事實,而不是
埋在一份設定清單裡的知識。

**失去**:離線把整個產品跑一遍的能力。dev 環境需要後端在跑。

**目前仍未落地的**:`GET /directory` 是 stub、`artifactApi.unpublish` 沒有 UI 呼叫端、
Schedule 頁面只有標題。Session 的改名/釘選/刪除與 Artifact 的刪除/分享/發布都已接真
後端,不再停用。
