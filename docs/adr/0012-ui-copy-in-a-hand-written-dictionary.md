# ADR-0012：介面文案放在自建字典，不引入 i18n 函式庫

日期：2026-09-02
狀態：已採納

## 背景

介面需要中英切換，由使用者按一顆鈕決定（Agent 回覆的內容不在範圍內——那是後端產生的，
前端無從翻譯）。

盤點後，實際要處理的是 **82 條可見文案，分布 21 個檔案**。另外有三類長得像文案、但不能
一起處理的東西：

1. **後端擁有、用來比對的字串** —— `INTERRUPTED_TEXTS`、`REPAIR_RECORD_PREFIXES`、
   `DRAFT_SESSION_TITLE`。它們拿去和後端存下來的內容做位元組比對，翻譯不會改變使用者讀
   到什麼，只會讓比對失效，而失效沒有任何錯誤訊息。
2. **後端即時給的文字** —— 錯誤回應的 `message`、反問表單的 `field.label`。前端不擁有。
3. **`aria-label` / `title`** —— 恆為英文，548 處測試靠它們定位元件。

## 決議

**自建 typed 字典，不裝 i18n 函式庫。**

- `src/i18n/zhTW.ts` 是中文文案，也是形狀的來源；`en.ts` 的型別由它推導
- **巢狀物件，沒有字串 key**：`t.share.published`。打錯字不可能發生，全程有自動完成
- **帶變數的條目是函式**而不是佔位符模板
- 元件用 `useTranslations()`；純模組與 class component 用 `getTranslations()`
- **`aria-label` / `title` 不進字典**，維持英文
- wire 字串移到 `constants/wireStrings.ts`，檔名說出它不是文案
- 預設 zh-TW，不讀 `navigator.language`
- 測試維持預設中文、既有斷言不動；另補少數幾條測「切換確實生效」

## 理由

**漏翻是編譯錯誤。** `const en: Translations` 由 `typeof zhTW` 推導，中文加一條而英文沒跟
上，`npm run build` 就失敗。函式庫給的是執行期的 fallback 或一個 missing-key 佔位符——那
要有人切過去才看得見。以兩種語言、82 條文案的規模，這個保證比函式庫的功能有價值。

**函式庫的功能用不到。** 複數規則、命名空間、按需載入、日期在地化格式，這裡一項都不需要。

**函式而非佔位符，是為了語序。** 中文「最多 5 個檔案」、英文「Up to 5 files」，變數位置
不同。佔位符模板會逼後譯的語言遷就先寫的那個語言的句構。

**`aria-label` 不翻是成本判斷，不是正確性判斷。** 翻譯它們對使用螢幕閱讀器的中文使用者
更正確，但會讓這件事從「82 條文案」變成「548 處測試改寫」，成本差一個量級。**若日後有無
障礙需求要推翻這一條，要知道推翻的代價在測試而不在文案。**

## 2026-09-03 追記:第二輪抽取

初版只收了 82 條;深度審查發現另有 60+ 條可見文案寫死英文(session rail、Gallery
標頭、Connectors 面板、檔案 modal、composer、各空狀態),已於第二輪全部入典,並補
`noBareLiterals.test.ts` 掃元件裸英文字面量——「漏翻是編譯錯誤」只對已入典的條目成
立,這條測試補上「沒入典」那一半。例外(送給後端的 prompt 文字、產品名、wire 標籤)
逐條列在測試裡並附理由。

## 代價

- 兩份字典靠型別對齊，但**型別擋不住「英文欄位原封抄了中文」**——那編譯得過。補了一條
  測試逐項比對兩份字典，`Submit` 這種兩語同字的例外明列。
- 英文文案由開發者草擬，沒有母語者審過。
- 語言存在 localStorage，換一台機器要重選一次。

## 順帶修正的詞彙

`CONTEXT.md` 的 Artifact 條目本來就寫著 `_Avoid_: Dashboard, Report, Output`，而版本選單
與 Artifact 面板用的「產出」正是 Output 的中文——詞彙表禁止了它，只是沒人把中文寫法對上
英文。`ArtifactPanel` 甚至在同一句話裡兩個詞都用了。抽取時一併統一為 Artifact，並把中文
寫法明確補進 _Avoid_。

「儀表板」一併改掉，理由更強：`Artifact.type` 不在契約裡，前端無從得知那個東西是 dashboard
還是 slides，寫下去是斷言一件查不到的事。後端存下的修復紀錄仍用「儀表板」且會出現在同一段
對話串裡——用詞不一致已列入後端待辦，那比前端斷言一個它不知道的型別好。

## 補充(2026-09-04):測試固定跑英文

上面「測試維持預設中文、既有斷言不動」那一條已經不成立。現在 `src/test/setup.ts` 在
`beforeEach` 把語言固定成英文。

原本那條只在「這些字串還沒入典」的時候才成立。入典之後,行為測試的斷言會跟著文案編輯跑
——改一句中文文案就得回頭改一批跟文案無關的測試。固定一種語言把這個耦合切斷:字典本身
已經有自己的守衛(型別對齊、逐條比對測試,以及 `languageSwitch.test.tsx` 證明切換有效),
其餘測試都是在測行為,跑哪種語言不影響它們要驗的事。

用 `beforeEach` 而不是 `beforeAll`:切換語言的測試不能把它的選擇洩漏給下一個。

**為什麼補在這裡而不是留在程式碼裡。** 這個修訂先前只寫在 `setup.ts` 的註解,而且那段註解
自稱「Revises ADR-0012」——等於一則程式碼註解在修訂一份決策文件,但文件本身沒有更新。
讀 ADR-0012 的人會得到相反的結論,而且他沒有理由知道要去 `setup.ts` 比對。決策現在回到
這份文件,`setup.ts` 的註解只留現行理由並指向這一段。
