# 0018. 來源種類綁定後不變,預設 Connectors只是新對話的起點

**背景。** 一場 Session 只用一種來源種類:Connectors 或上傳的檔案(CONTEXT.md 已選來源)。
原本的規則是「清掉其中一種就能換另一種」。同時,想要一個像 Claude 那樣的體驗:使用者有一組
跨對話的預設 Connector,新對話不用每次重選。兩件事撞在一起:預設若在開新對話時就掛上去,
新對話就永遠不能附檔案。

**決定。** 兩條規則,2026-09-18 定案:

1. **來源種類(Source kind)在第一次掛上其中一種時由後端定下,之後不變。** 把已選來源清空、
   把檔案刪光或全部過期,種類都還是原來那一種,另一種的入口仍然關著;要換種類就開新對話。
   後端會在 `SessionDetail` 加一個唯讀、三態的欄位(未定 / files / connectors)承載它,由後端
   從 files 與 connectors 推導。欄位到之前,前端仍由 `files.length` / `connectors.length` 推
   (`sourceKindOf`,唯一一處),此時「清空後不變」做不到——前端沒有地方記一個後端沒記的事實,
   接受這段過渡。
2. **預設 Connectors(Default sources)是使用者的,只當新對話第一次打開 Connectors 面板時的預選。**
   它從不代替使用者寫進任何 Session:使用者按了送出才算選,所以草稿在綁定前仍是未定,附檔案
   照樣開著。它只在偏好設定裡改;在某一場對話裡送出**不再**順便改掉它——先前的「上次送出的
   組合」就是這樣悄悄被每一場對話改寫的,所以那個隱含記憶拿掉,既有的值一次性遷移成預設。
   目前暫存在瀏覽器本機,將來搬到後端成為使用者設定;`useDefaultConnectors` 是唯一的接縫。

**沒選的路。** (a) 開新對話時就把預設寫進 session:違反 ADR-0005(草稿在後端不存在),而且
會產生一批空 session,還會讓附檔案永遠被擋。(b) 第一次送出時若沒附檔案就先寫預設再送訊息:
做得到「開了就能用」,但第一次送出變成兩個請求,中間失敗要處理,而且要先確認 PATCH 對草稿
id 的行為;等使用者設定真的搬到後端時,由後端在 upsert 時套用預設會乾淨得多,所以現在不做。
(c) 取消「一場只用一種」:那是後端 Scenario 的能力問題,不是前端能決定的。

**後果。** 「+」選單被擋住的那句話從「清除後才能…」改成「…要用檔案/Connectors 請開新對話」,
Connectors 面板的唯讀說明同理。Claude 的「每場預設全開、關掉不要的」沒有採用:這裡的預設
是「面板開在這組上」,使用者仍要按送出,因為綁定是不可逆的,不該由預設替他按。
